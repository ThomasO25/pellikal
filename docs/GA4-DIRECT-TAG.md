# GA4-DIRECT-TAG.md

The GA4 **base** tag (`G-J8SQ4CC7BT`) moved from "a Google Tag inside GTM" to
"the page's own Google tag (gtag.js)" on **7 October 2026**. GTM
(`GTM-MK2PHWB`) stays on every tracked page for everything else.

**Status: built and verified locally. NOT published. NOT verified against
Google's live endpoints or the live GTM container — see §7.**

---

## 1. Why

Live browser testing (Chrome Incognito, same profile for both sites):

| | Apex Lift Solutions (direct gtag.js) | Pellikal (GA4 via GTM) |
|---|---|---|
| `gtag/js?id=G-…` | 200 | **`net::ERR_BLOCKED_BY_CLIENT`** (the request GTM initiates) |
| `/g/collect` page_view | 204 | never generated outside GTM Preview |
| GTM, Consent Mode, Conversion Linker, `generate_lead`, Ads conversion | — | all working |

`ERR_BLOCKED_BY_CLIENT` is the browser (an extension or filter list) refusing
the request; nothing on the server side produces it. The direct loader and
GTM's loader fetch from the **same host** (`www.googletagmanager.com`) — the
difference is the URL GTM builds (`…/gtag/js?id=G-…&l=dataLayer&cx=c&gtm=…`)
versus the plain `…/gtag/js?id=G-…` that a page-level install requests, and
the fact that one is initiated by `gtm.js` and the other by the document.
Whether a given blocker treats them differently is exactly what the live test
in §7 decides. **If the direct request is also blocked, this migration is not
published** (brief §9).

## 3. The head, in execution order

All three pieces are generated by `tools/build.py` → `gtm_head()` into the
single `<!-- @partial:gtm-head -->` region, so they cannot be reordered by
hand and a rebuild always restores them:

```
 1. window.dataLayer exists                       ┐
 2. window.gtag exists                            │ Consent Mode v2 block
 3. gtag('consent','default', {…denied…, region:[EEA+GB+CH]})   (unchanged, v24)
 4. gtag('consent','default', {…granted…})        │
 5. gtag('set','ads_data_redaction', true)        │
 6. saved Accept/Reject → gtag('consent','update', …)   synchronous   ┘
 7. <script async src="https://www.googletagmanager.com/gtag/js?id=G-J8SQ4CC7BT">
 8. gtag('js', new Date()); gtag('config','G-J8SQ4CC7BT')   ← NEW, guarded (see below)
 9. GTM container snippet (GTM-MK2PHWB) → gtm.start                     (unchanged)
```

Lines 7–8 are Google's stock Google-tag snippet **minus** its two middle
lines (`window.dataLayer = …` and `function gtag(){…}`), which are
intentionally absent because the consent block already created both. One
dataLayer, one `gtag()`, one consent implementation. `gtag.js` loads
asynchronously, but what matters is the *queue*: by the time it executes, the
dataLayer already holds the regional defaults, any saved choice, and then the
config — in that order — and it replays them in order. The direct tag
therefore gets exactly the consent guarantees GTM's Google Tag had.

The config is wrapped in
`if (window.PELLIKAL_CONSENT_SETTINGS && typeof window.gtag === 'function')`.
`PELLIKAL_CONSENT_SETTINGS` is the first statement of the consent block, so if
that block were ever missing from a page, GA4 would simply **not be
configured** there instead of running on Google's implicit "granted".

**Exact generated snippet** (as stamped into every tracked page):

```html
<script async src="https://www.googletagmanager.com/gtag/js?id=G-J8SQ4CC7BT"></script>
<script>
if(window.PELLIKAL_CONSENT_SETTINGS&&typeof window.gtag==='function'){
gtag('js',new Date());
gtag('config','G-J8SQ4CC7BT');
}
</script>
```

Pages carrying it: the 13 tracked public pages (`/`, residential, commercial,
window-inserts, contact, about, faq, solutions, privacy, terms, accessibility,
`/thankyou/`, `404.html`). Not on `/admin/` or `/local-law-97/`
(`excludeFromTracking`), which carry no Google code at all.

## 4. The GTM tag that MUST be paused — manual, before publishing

The container cannot be edited from the repository. In GTM-MK2PHWB:

| | |
|---|---|
| **Tag name** | `GA4` |
| **Tag type** | Google Tag |
| **Tag ID / destination** | `G-J8SQ4CC7BT` |
| **Current trigger** | Initialization – All Pages |
| **Action** | **Pause** (tag menu → Pause). Do **not** delete it until §7 has passed — it is the rollback. |

While the page carries the direct tag *and* this GTM tag is live, every page
view is sent twice (two `config` commands for one ID, each with
`send_page_view`). Sessions, engagement rate and bounce rate are all wrong
from that moment. Pause it in the workspace first, test in Preview (§7), and
only then publish both the site and the container.

## 5. How the GA4 custom events keep working

The site pushes its events to `window.dataLayer` exactly as before —
`quote_cta_click`, `quote_form_view`, `quote_form_start`, `quote_form_error`,
`click_to_call` / `click_to_text` / `click_to_email`, `contact_form_submit`,
`homepage_form_submit`, `generate_lead`, `window_insert_lead`,
`view_contact_page`, `consent_update`. Nothing was renamed, added or removed
(`js/tracking.js` is behaviour-identical to v24).

> **Naming note for the owner's event list:** the brief refers to
> `phone_click` / `text_click`. The site has never pushed events by those
> names; its dataLayer events are `click_to_call` and `click_to_text`. If GA4
> shows `phone_click`/`text_click`, that renaming is happening inside the GTM
> tag; if it does not, the GA4 event names are `click_to_call`/`click_to_text`.
> Nothing in this change touches either.

They reach GA4 through the existing GTM tag **`GA4 - Pellikal Custom Events`**
(Google Analytics: GA4 Event, Measurement ID `G-J8SQ4CC7BT`). A GA4 *event*
tag needs a Google tag for the same Measurement ID to be loaded on the page;
with the page now loading it directly, the event tag sends through that
instance. If GTM does *not* find a loaded Google tag for the ID, it loads one
itself — which in the blocked browser would be the same `ERR_BLOCKED_BY_CLIENT`
again and the events would be lost. That is why §7 explicitly checks for a
**second** `gtag/js?id=G-J8SQ4CC7BT` request after a custom event fires.

**Decision rule (brief §4):** no `gtag('event', …)` has been added to the
site. Only if §7 proves the GTM event tag cannot send through the page's
Google tag does a direct event bridge become an option — and then the GTM
event tag would have to be paused at the same time, never both. Duplicate
custom events are worse than a short gap.

The Google Ads conversion (`Google Ads Conversion - Form Fill`, trigger
Custom Event `generate_lead`, Count One), the Conversion Linker and Microsoft
Clarity are untouched and remain in GTM.

## 6. GA4 property settings to verify (manual, in the GA4 admin)

Nothing below is code. **Do not hand-code events that Enhanced Measurement
already provides.** GA4 → Admin → Data streams → *Pellikal web stream* →
Enhanced measurement:

| Option | Setting | Why |
|---|---|---|
| Page views | **ON** (required) | the `page_view` the direct tag sends |
| Scrolls | **ON** | `scroll` at 90 % depth — the "scroll" metric in the goals list |
| Outbound clicks | **ON** | `click` with `link_url` for links leaving the site (Indow, LLumar, etc.) |
| Site search | leave default | no site search on pellikal.com; nothing triggers it (`?service=` / `?consent=reset` are not search parameters) |
| Video engagement | leave default | no embedded YouTube players |
| File downloads | leave default | no downloadable files |
| **Form interactions** | **OFF** | GA4 would emit its own `form_start`/`form_submit` for the quote form — `form_submit` fires on the submit *attempt*, including validation failures and Formspree errors, so it is **not** a lead and would be confused with `generate_lead`. The site's own `quote_form_start` / `quote_form_error` / `generate_lead` are the precise versions. Also keeps `form_submit_text` and friends out of reports. |
| Page changes based on browser history events | leave default | static multi-page site; not applicable |

Also in GA4 admin:

- **Admin → Events → mark `generate_lead` as a Key event.** It is the
  successful-form signal. Do **not** mark `page_view` of `/thankyou/`,
  `contact_form_submit`, `click_to_call` or `click_to_text` as key events —
  those are diagnostics (the Google Ads conversion stays separate, in GTM, on
  `generate_lead`).
- **Admin → Custom definitions → event-scoped custom dimensions:**
  `form_location`, `cta_location`, `error_type`, `service`, `lead_source`,
  `page_type`, `click_location`. Without these the parameters are collected
  but never appear in reports.
- **Data retention:** 14 months (Admin → Data settings → Data retention).
- **Google signals:** an owner decision, not required for any goal below;
  leave off unless remarketing audiences in GA4 are wanted (Ads remarketing
  already runs through the Ads tag in GTM).
- No PII is collected by any of this: the site pushes no names, phone
  numbers, email addresses or ZIPs to the dataLayer (verified by both suites),
  and Enhanced Measurement never reads field values.

### Where each goal is read (standard reports unless noted)

| Goal | Where |
|---|---|
| active users, new users, sessions | Reports → Life cycle → Acquisition → *Overview* / *User acquisition* |
| returning users | Reports → Retention (new vs returning); Explore → segment "returning users" |

| phone / text clicks | Engagement → *Events* → `click_to_call`, `click_to_text` (or the names the GTM tag maps them to — see §5) |

## 7. Required live verification — before anything is published

**Step 0 — in GTM (workspace, not published):** pause the Google Tag `GA4`
(`G-J8SQ4CC7BT`, Initialization – All Pages). Leave `GA4 - Pellikal Custom
Events`, `Google Ads Conversion - Form Fill`, the Conversion Linker and
Clarity as they are.

**Step 1 — Chrome Incognito, NO Tag Assistant / GTM Preview,** DevTools →
Network, load the built site (a staging copy or a local build served over
http). Expect:

| Request | Expect |
|---|---|
| `www.googletagmanager.com/gtag/js?id=G-J8SQ4CC7BT` | **200** — initiated by the document (Initiator column shows the page, not `gtm.js`) |
| `www.googletagmanager.com/gtm.js?id=GTM-MK2PHWB` | 200 (as before) |
| `…google-analytics.com/g/collect?v=2&tid=G-J8SQ4CC7BT&…&en=page_view…` (host may be `region1.google-analytics.com` or `analytics.google.com`) | **204**, exactly **one** per page load, `tid=G-J8SQ4CC7BT`, `en=page_view` |
| GA4 → Reports → Realtime | the visitor appears |

If `gtag/js?id=G-J8SQ4CC7BT` still shows `net::ERR_BLOCKED_BY_CLIENT` here:
**stop, do not publish, report that result.** The block is in the client and
moving the tag did not get past it.

**Step 2 — connect GTM Preview (Tag Assistant)** to the same site and check,
with the GTM `GA4` tag still paused:

- `page_view`: exactly **one** `/g/collect` with `en=page_view` per page
  (the direct tag's). The paused GTM tag sends none.
- scroll to the quote form → `quote_form_view` **once**; type → `quote_form_start`
  **once** (one `/g/collect` each, `tid=G-J8SQ4CC7BT`).
- **No second `gtag/js?id=G-J8SQ4CC7BT` request appears when the GTM event tag
  fires.** If one does, GTM did not use the page's Google tag (§5) — in the
  blocked browser it will show as blocked and the events will be missing in
  GA4. Report it; do not add a `gtag('event')` bridge without that evidence.
- submit the form with real details (Formspree live): `generate_lead` **once**
  in the dataLayer, **one** `GA4 - Pellikal Custom Events` hit for it, and
  `Google Ads Conversion - Form Fill` fires **once**, on the form page, before
  the redirect.
- `/thankyou/`: one `page_view`, no Ads conversion, no second
  `generate_lead` (refresh and Back/Forward do not add any).
- GA4 Realtime → Events: `page_view`, `quote_form_view`, `quote_form_start`,
  `generate_lead` each counted once for that session.

**Step 3 — consent (regional defaults, v24):** from `?consent=reset`, Tag
Assistant → Consent tab: the On-page Default rows are unchanged (denied ×4
for a simulated Spain/UK/CH location, granted ×4 from New York), the saved
Reject is restored before `Container Loaded`, and with Reject chosen the GA4
hits are cookieless (`gcs=G100` in `/g/collect`). The direct tag must show
the same consent state as GTM's tags in the Consent tab.

Only after Steps 1–3 pass: publish the site, publish the container with the
`GA4` tag paused, re-check Step 1 once against the live domain. Keep the
paused tag for at least a reporting week before deleting it.

## 8. Risks of duplicate tracking

| Risk | Effect | Guard |
|---|---|---|
| GTM Google Tag `GA4` not paused while the direct tag is live | 2× `page_view`, sessions/engagement/bounce wrong | §4; build summary reminder; Step 2 counts hits |
| GTM GA4 event tag loads its own `gtag.js` instead of using the page's | events still single, but a second library load (blocked in the test browser → events lost) | Step 2 "no second loader" check |
| Enhanced Measurement *Form interactions* on | `form_submit` fires on failed attempts too; looks like a lead | §6: OFF |
| `page_view` of `/thankyou/` treated as a conversion / key event | counts refreshes and revisits as leads | never a trigger (LEAD-FLOW.md); key event is `generate_lead` only |
| a `gtag('event', …)` added to page code **and** the GTM event tag kept | every custom event twice | brief §4: none added; decision rule in §5 |
| legacy GTM tags (`GA4 Event - Contact Form Fill` on the thank-you page view, Clarity unpaused, old GA4 property `G-TPD5SKWWVC`) | double reporting / wrong property | still on the manual GTM checklist in LEAD-FLOW.md |
| `ga4DirectTag` left true after a rollback publish of the container | the GTM tag and the direct tag both live again | rollback order below |

## 9. Rollback

1. `site.config.json` → `"ga4DirectTag": false`.
2. `python3 tools/build.py` (twice; second run `Pages updated: 0`). The loader
   and the config disappear from every page; nothing else changes.
3. Publish the site.
4. In GTM, un-pause the Google Tag `GA4` (`G-J8SQ4CC7BT`) and publish the
   container.

Do 3 before 4 (a brief gap with no page views is harmless; an overlap counts
twice). Both QA suites run clean in either mode — the checks read
`ga4DirectTag` and assert "exactly one direct tag" or "no direct tag"
accordingly.
